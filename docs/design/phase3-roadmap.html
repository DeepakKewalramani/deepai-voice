Phase 3: Live Translator

System audio capture, streaming STT per channel, real-time translation, and subtitles. Demo target: 3-minute bilingual call end-to-end.

Overview

Goal: Extend dictation to live calls. Capture audio from Zoom, Meet, Teams and similar apps ("system audio"), run streaming speech-to-text on two channels (user + others), translate each segment to chosen languages, and display live subtitles with suggested replies.

Branch: phase-3-translator

Demo check: Full 3-minute test call with recording, bilingual subtitles, and suggested reply.

Slices (target ~300 LOC each)

3.1 System audio capture

Owns: src-tauri/src/audio/system.rs, system tap interface, tests

Goal: Capture audio from the system ("Others" channel) via ScreenCaptureKit (macOS 14+) or fallback to CoreAudio tapClient. Separate from mic: two parallel channels on the overlay.

Done looks like:

  • System audio muted locally (rule 8: user's own speaker is not intercepted)
  • Unit tests: fake tap returns audio, stop disables, permission checks work
  • Real manual check: Zoom/YouTube audio captured and level meters move
Depends on: Phase 1 (audio module, level meter)

3.2 Streaming STT with auto language detection

Owns: src-tauri/src/stt/streaming_session.rs, language detection, tests

Goal: Wire the streaming engine (2.11) into live audio from both channels. Auto-detect language and route to the right STT provider. Emit partial and final events per channel.

Done looks like:

  • English-only: on-device Speech framework for both channels
  • Hinglish/Hindi: Sarvam or Deepgram with auto-detect, fallback to English on error
  • Real manual check: Zoom + Hindi-mix audio → English + Hinglish subtitles live
Depends on: 3.1 (system audio), 2.11 (streaming engine), 2.7 (cloud STT adapters)

Risks and rollback

  • System audio tap: ScreenCaptureKit is new (macOS 14+); older Macs need CoreAudio tap (complex). Fallback: local audio only, skip system tap.
  • Call app detection: Zoom, Meet, Teams all route audio differently. Manual testing on each needed; failures are app-specific, not platform.
  • Translation latency: Each segment waits for Haiku (~1.5s). If unacceptable, pre-gen suggestions or template bank instead.
  • Rollback: Revert to Phase 2 main; no data migration needed (new features only).
