- Phase: 2 | Branch: phase-2/2.13-provider-hub

## Goal
Build the provider hub tab in Settings: a curated catalog of the best providers per capability (STT, LLM, TTS), each with a one-tap Connect action (masked key entry, key stored in the OS credential store, never in settings.json) and a connected/not-connected status. The catalog lists presets for Sarvam, Deepgram, ElevenLabs and the generic OpenAI-compatible path; translation uses the LLM chain (phase 3 slice 3.4), so no separate catalog category is needed.

## Owns (only these files may be changed)
- src/settings/providers/ (new directory: catalog UI, connect form, status)
- src-tauri/src/providers/catalog.rs (new: static catalog table, one entry per adapter preset)
- src-tauri/tests/provider_catalog_test.rs
- docs/tasks/2.13.md

## Catalog presets (FACT from docs/research/providers-findings.md, 31 Oct 2026)
- STT:
  - Whisper local `base.en` (built-in, offline, English only)
  - Apple Speech on-device (built-in, offline, via slice 2.11)
  - Sarvam Saaras (`saaras:v3` codemix, `saaras:v4` default; Hindi + 22 Indic; Rs 0.49/min)
  - Deepgram Nova-3 (Hindi `hi`; pre-recorded $0.0052/min)
  - Gnani.ai ASR (candidate; API shape, pricing and Hindi support UNKNOWN, verify before listing as connectable)
- LLM (cleanup, translation, suggested replies):
  - Anthropic Claude (native adapter, Haiku default)

- TTS:
  - ElevenLabs (Flash v2.5 English; Multilingual v2 / v3 for Hindi)
  - Sarvam Bulbul v4 (Hindi, Rs 1 per 1k chars)
  - macOS built-in `say` (offline fallback, Hindi Lekha voice installed)

## Done looks like (testable)
- [ ] Settings > Providers shows one section per capability (STT, LLM, TTS) with the catalog entries above.
- [ ] Each catalog entry has a Connect action: masked key input, "Set" button. The key goes to the credential store via a Rust command; the UI receives only "set"/"not set" and the last 4 characters.
- [ ] Connect writes a provider config entry (`id`, `kind`, `adapter`, `model`, `keyRef`) to settings.json alongside the existing `providers` list; the entry appears in the chain editor of slice 2.8.
- [ ] Status per provider: connected/not connected, derived from `keyRef` presence, with the masked tail shown.
- [ ] Gnani and any provider not verified against current docs is shown as "candidate" with a note, not as a fully supported preset.
- [ ] Vitest tests: catalog renders from the Rust catalog endpoint, connect form validates input, key never appears in settings.json or logs.
- [ ] Manual check: connect Sarvam key in Settings, restart app, the provider still shows connected and appears in the STT chain.

## Built (claude-main subagent, 1 Nov 2026)
- Rust: `src-tauri/src/providers/` (`mod.rs` enums, `catalog.rs` static table, `hub.rs` connect/disconnect/status over settings.json plus the existing `settings::keys::KeyStore`, `commands.rs` Tauri commands). Registered in `src-tauri/src/lib.rs`: `provider_catalog`, `providers_status`, `connect_provider`, `disconnect_provider`, `open_provider_docs` (plus the 2.14 commands).
- Settings: `Provider` gained optional `name` and `authStyle` (additive, skipped when empty). An old file without them loads and round-trips unchanged (test `older_settings_without_new_fields_load_and_round_trip_unchanged`). `tests/settings_test.rs` literal got the two new `None` fields, nothing else changed.
- Keys: only in the OS credential store, service `com.deepakkewalramani.deepaivoice`, account `provider:<id>`. settings.json gets `{id, kind, adapter, model, baseUrl?, keyRef, authStyle?, name?}`. The UI gets `set`/`not_set`/`not_needed` and the last 4 characters (keys of 8 or more only). Errors are fixed sentences, never the key.
- Catalog (FACT from R.4 and R.10): STT Local Whisper and Apple on-device (built in), Sarvam Saaras, Deepgram Nova-3, ElevenLabs Scribe, AssemblyAI, Groq Whisper, Soniox, Smallest.ai Pulse (verified), Any OpenAI-compatible (via Make your own), Reverie and Gnani Vachana (candidate, cannot connect, reasons in the note). LLM Anthropic, Any OpenAI-compatible, Ollama. TTS ElevenLabs, Sarvam Bulbul, Smallest.ai Lightning, macOS voice (built in). No OpenAI TTS. Not listed (R.10): Bhashini, Google, Azure, Speechmatics.
- UI: `src/settings/providers/` replaces the Providers tab content (mounted in `SettingsShell.tsx`). Built-in Whisper still shows when no catalog is loaded. Dev preview: `?providers=connected|empty|error` in `npm run dev` outside Tauri, using `catalog-preview.json`, kept equal to the Rust catalog by a test and absent from the production bundle (checked with grep on `dist/`).
