# 2.11: Streaming STT engine (on-device macOS Speech)

- Phase: 2 | Branch: phase-0-foundation (working tree, not committed)
- Dependency approved by human: objc2-speech, objc2-avf-audio, objc2-foundation 0.3.2 (see docs/INSTALLED.md)

## Design
- `src-tauri/src/stt/streaming.rs`: `StreamingStt::start(locale) -> Box<dyn StreamingSession>`. A session has `push_audio(&[f32])` (16 kHz mono), `events() -> &Receiver<StreamEvent>` (std mpsc), `finish()` and `cancel()`. `StreamEvent` is `Partial`, `Final` or `Error(ProviderError)`. Also `collect_final` and `FakeStreamingStt`.
- `src-tauri/src/stt/apple_speech.rs`: `AppleSpeech` (macOS only). `SFSpeechAudioBufferRecognitionRequest` with `requiresOnDeviceRecognition = true` and `shouldReportPartialResults = true`. `start` returns `Unsupported` when the locale has no recogniser, falls back to another language, or cannot run on device. There is no server fallback. It returns `Auth` when permission is not granted.
- Threading: all Objective-C objects live on one worker thread, which takes commands over mpsc. Results arrive on a private `NSOperationQueue` (not the main queue). The result block owns only Send + Sync data and copies text out during the call. After `Final`, `Error` or `cancel` the event sender is dropped, so the receiver disconnects. `finish` waits up to 20 s, then sends `Timeout`.
- Permission seam: `SpeechPermissionProvider` and `map_speech_authorization_status` (0 Undetermined, 3 Granted, anything else Denied). Real provider: `SfSpeechPermission`.
- Info.plist: added `NSSpeechRecognitionUsageDescription`.

## Real run (1 Nov 2026, throwaway bundled probe app, not in repo)
A scratch .app linking `deepai_voice_lib` with `NSSpeechRecognitionUsageDescription`, fed the fixtures in 100 ms chunks at real-time pace, en-US.
- Permission: Undetermined, prompt shown, granted, then Granted. `SfSpeechPermission.request` works from a bundled app.
- On-device en-US assets: present (start succeeded with on-device required). First start 625 ms, later starts 5 to 45 ms.
- Partials: first word 0.7 to 2.4 s after audio start, then a new partial roughly every 100 to 300 ms. Final 0.2 to 2.2 s after `finish`; one outlier 6.2 s (04 technical terms).
- Finals: 01 exact; 02 "pool request" for "pull request"; 03 exact (no fillers in this fixture's output); 04 "DJI voice runs on Tori version two with rust and react"; 05 "Meeting at 3 PM with 12 engineers in room four". No punctuation in any final.
- Silence (06): `Error(Local("speech recognizer error domain=kAFAssistantErrorDomain code=1110"))` after 1.1 s. 1110 is commonly reported as "no speech detected" (INFERENCE, not checked against Apple docs); likely should map to an empty result, not an error.
