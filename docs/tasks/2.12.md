# 2.12: Streaming engine in dictation (instant typing), Whisper reliability

- Phase: 2 | Branch: phase-0-foundation (working tree, not committed) | Base: 95fea24
- No new crates, no Cargo.toml or lib.rs edits.

## Design
- Engine per hold (`dictation/engine.rs`, pure): `choose_engine(setting, permission, support)`. Streaming only for setting Auto, permission Granted and en-US OnDevice. Every fallback has a fixed reason (`Fallback::status`), logged as `dictation engine=whisper reason="..."`. A failed engine start also falls back (`StartFailed`). Undetermined permission: requested once per run, only from the bundled app (`should_request_permission` + `autostart::bundle_path`), Whisper for that hold.
- Setting: no backend settings store exists for General (the settings UI keeps values in memory only), so the engine is read from env `DEEPAI_ENGINE=whisper` (anything else is Auto). No Speech engine select was added to Settings > General.
- Streaming loop (`dictation/stream_hold.rs`, pure over `StreamingStt`): recorder drains every 50 ms into the session. Each session is one segment. Partials become `Input::StreamPartial`; the machine types every word except the newest last one (`stream_text::eager_stable_text`), only extending what was typed. Session final goes through the existing `reconcile` (Backspace limited to this segment). Restart at 600 ms silence after text or after 50 s; old session finishes while the new one gets audio, and newer events are read only after the older final (order kept). Engine error or "no speech" at finish: the last partial (or nothing) is the result. Esc: `cancel()` on every session, nothing more sent; hold ids still drop late events.
- Whisper reliability: adaptive voice gate (`live::NoiseFloor`: floor tracks quiet frames, rises about x e per 3 s, voice = 2.8x floor, minimum 0.002), floor carried across holds, onset 180 ms (150 ms would break the existing test that ignores a 150 ms blip). Safety net: a hold with zero segments, >= 0.4 s and RMS > 0.0001 transcribes the whole hold audio (kept up to 120 s). Partials use `audio_ctx = clamp(ceil(s*50), 256, 1500)` (whisper-rs 0.16.0 `set_audio_ctx`); finals keep full context and greedy. Partial cadence: due after max(300 ms, last partial cost), only when the queue is idle. Threads: physical cores minus 1, 2..8.
- Diagnostics (names and numbers only): `dictation event=hold_no_segment hold_ms audio_ms`, `event=safety_net_used audio_ms`, `event=partial_skipped_busy count hold_ms`, plus `audio_ctx` in `local_whisper event=transcribed`.
- Permissions: optional Speech Recognition row (`speechRecognition`, pane `Privacy_SpeechRecognition`, Request access only from the bundled app). Frontend shows it when the backend reports it; it never counts as missing.
