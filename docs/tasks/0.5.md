## Goal
Implement secure logging using tracing and tracing-subscriber with redaction for API keys (e.g. sk-ant-*, Bearer tokens) and spoken transcripts or audio data, logging lengths and counts only.

## Owns (only these files may be changed)
- src-tauri/src/logging/ (all files)

- src-tauri/Cargo.toml (additive dependencies only: tracing, tracing-subscriber, regex)
- docs/INSTALLED.md (dependency log)
- docs/tasks/0.5.md

## Done looks like (testable)
- [ ] Tracing subscriber initialized via init_logging() with configurable env filter (RUST_LOG with default fallback to info).
- [ ] Pattern-based redaction layer or formatter for logs that scrubs API keys: Anthropic keys (sk-ant-*), generic API keys (sk-*), Bearer tokens, and arbitrary secrets.
- [ ] Structured event logging helpers for pipeline stages (Audio, STT, LLM, Paste) logging durations, sample counts, character lengths, status codes, and request IDs only.
- [ ] Explicit verification that raw audio buffer samples are never logged or formatted.
- [ ] Explicit verification that spoken transcript text and cleaned text are never logged directly in pipeline events (lengths only).
- [ ] Test verifying that logging a string with sk-ant-api03-* results in redacted output like [REDACTED_KEY].
- [ ] Test verifying that logging an STT or LLM response logs only text_len and metadata, with zero transcript words in log stream.
- [ ] Comprehensive unit tests in src-tauri/tests/logging_test.rs pass with cargo test --test logging_test.

## Tests
- Automated: cargo test --test logging_test
- Manual:
  1. Set RUST_LOG=debug and run cargo test --test logging_test -- --nocapture.
  2. Inspect captured log records to verify that secret strings and transcript words are absent.
  3. Verify log output format is clean, readable, and conforms to security rules.
