## Goal
Add the "Make Your Own" form to the provider hub: the user defines a custom provider by choosing a capability (STT, LLM, TTS), entering a base URL, API key, model ID and protocol (OpenAI-compatible by default). A Test Connection command sends a minimal ping from Rust and reports latency or the auth/parse error. The resulting provider is stored like any built-in and joins the chain editor.

## Done looks like (testable)
- [ ] Form fields: name, capability (STT/LLM/TTS), base URL, API key (masked), model, protocol (OpenAI-compatible default). Inputs validated in the UI (URL scheme, required fields).
- [ ] Submit writes a provider config entry with `adapter` set to `openai_compatible` for the custom protocol, `baseUrl`, `model`, `keyRef`; the key itself goes only to the credential store.
- [ ] Test Connection runs a minimal request from Rust (LLM: `POST {base}/chat/completions` with a 1-token prompt; STT: `GET {base}` or a lightweight probe per adapter) and returns latency or a classified error (`Auth`, `Network`, `BadRequest`, `Server`).
- [ ] Local endpoints (`localhost`, `127.0.0.1`) are flagged as on-device in privacy (dataLeavesDevice false); everything else is cloud.
- [ ] Unit tests: fake HTTP server answers a ping, returns a 401 and a 500; the command classifies all three correctly. Settings JSON never contains a key value.
- [ ] Manual check: add an OpenAI-compatible endpoint (for example Ollama `/v1`), Test Connection succeeds, provider appears in the LLM chain.

## Built (claude-main subagent, 1 Nov 2026)
- Rust: `src-tauri/src/providers/custom.rs` (pure validation), `hub.rs` (`save_custom`, `delete_custom`, `test`), `probe.rs` (`HttpProbe` seam, typed `TestResult`), `http.rs` (`UreqProbe`, ureq 3.5.0 added by the main session with the human's approval). Commands `save_custom_provider`, `delete_custom_provider`, `test_provider`. File names differ from the planner's (`commands/test_connection_cmd.rs`, `tests/test_connection_test.rs`): the work lives in `providers/` and `tests/provider_catalog_test.rs`.
- Rules: name 1 to 40 characters; base URL https, or http only for localhost, 127.0.0.1, ::1; no user or password, query or fragment; lowercased scheme and host, trailing slash removed; model 1 to 80, no spaces; auth bearer (default), token, x-api-key, none, or a custom header name that is a legal HTTP token (not Host, Content-Length and other app-managed headers; `X-API-Key-ID` and `Api-Subscription-Key` accepted); protocol OpenAI-compatible only. Same rules in `src/settings/providers/validate.ts`; both sides run `validation-vectors.json`.
- Test connection: runs only on the button. `GET {baseUrl}/models`, connect timeout 5 s, total 10 s, redirects never followed, no proxy, key only in the one auth header. Returns only `ok` (latency), `key_rejected` (401/403), `not_found`, `unreachable`, `timeout`, `other(status)` or `not_available` (reason). Catalog entries return `not_available`: R.4 and R.10 record no free check endpoint for them. Local endpoints are labelled "On this Mac" in the UI; the privacy flag in settings is not written yet.
