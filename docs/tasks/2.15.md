# 2.15: Dictionary (names and terms as hints and corrections)

- Phase: 2 | Branch: phase-0-foundation (working tree, not committed)

- Owner agent: claude-main builder subagent | Reviewer agent: TBD (different session)

## Goal
User problem: saying "my name is Deepak" typed "my name is people". Whisper base.en and the on-device streaming engine guess common words and had no way to get our vocabulary. The Dictionary page was a "Coming soon" card.

## Design
- Store: `dictionary.json` in the app data folder (same folder as `overlay.json`), `{version:1, entries:[{id, word, hearedAs, language, note}]}`, atomic write (temp file then rename), seeded with "Deepak" and "DeepakKewalramani" only when the file does not exist. Unreadable or invalid file: moved to `dictionary.json.bad`, an empty dictionary is used and saved (so the seed never returns). Invalid entries inside a valid file are dropped and the original is copied to `.bad`. No network. No word, sound-alike or note is ever logged or put in an error string.
- Limits (Rust and UI share `src/dictionary/validation-vectors.json`): 500 entries, word 1..60 chars without control characters, 0..5 sound-alikes of 1..60 chars, language `any` or a 2-3 letter ISO code, note 0..80 chars, case-insensitive duplicate words rejected.
- Per hold: the recorder thread reads the store once at hold start into `HoldVocab` (language `en` for both engines today). An edit applies from the next hold.
- Use 1, Whisper: `build_prompt` gives "Vocabulary: Deepak, DeepakKewalramani" (words only, deduplicated, language filtered, at most 40 words and 400 chars). Passed to final and partial passes through new `transcribe_with_hint` and `transcribe_partial_with_hint`; the old functions behave exactly as before (no prompt). The prompt is tokenized once with the model tokenizer and passed as prompt tokens: whisper.cpp turns `initial_prompt` into the same prompt tokens (whisper.cpp `whisper_full_with_state`), and whisper-rs `set_initial_prompt` leaks a CString per call.
- Use 2, streaming engine: `StartOptions { hints }` plus a default `StreamingStt::start_with` (existing engines and tests unchanged). The on-device engine sets `contextualStrings` (deduplicated, at most 100). No Cargo.toml change was needed: the `SFSpeechRecognitionRequest` feature already enables `objc2-foundation/NSArray`.
- Use 3, correction map: `apply_replacements` / `Replacer` rewrites whole-word, case-insensitive sound-alikes (multi-word across plain spaces, longest first, Unicode word characters including Devanagari signs), keeps a capital at a sentence start, one pass so no chains, never inside a longer word. Applied to every Whisper partial and final (whisper thread) and every streaming partial and final (`StreamHold` public outputs) before the machine sees them, so local agreement, preview and Backspace counts all run on corrected text.
- UI: Dictionary page in the existing look (note card, settings inputs and buttons, tokens only): add form, Add many, searchable list with count, inline edit (Esc cancels), delete with confirmation, empty, loading, error and limit states, next-dictation note. `useDictionary` wraps every invoke in try/catch; the in-memory fake (`preview.ts`) is used by tests and the dev browser only and is absent from the production bundle.
