## Goal
Implement versioned JSON settings storage with migrations and OS Keychain integration (via keyring crate) for API keys, ensuring keys are never stored in settings JSON.

## Owns (only these files may be changed)
- src-tauri/src/settings/ (all files)
- src-tauri/tests/settings_test.rs
- src-tauri/Cargo.toml (additive dependencies only: keyring, serde, serde_json)
- docs/INSTALLED.md (dependency log)
- docs/tasks/0.4.md

## Done looks like (testable)
- [ ] Schema definition in Rust matching ADR 0002 section 5: schemaVersion (starts at 1), hotkeys, providers list, chains, styles list, activeStyle, timeouts, privacy.cloudAcknowledged, maxRecordSeconds.
- [ ] Versioned JSON storage in OS app config directory (tech.tequity.deepaivoice in Application Support on macOS).
- [ ] Migration framework that runs ordered migrations when loading older schema versions (e.g. schemaVersion 0 fixture upgrades cleanly to schemaVersion 1).
- [ ] Corrupt settings file handling: creates a timestamped .bak backup file and safely loads default settings without panic or crash.
- [ ] Unknown newer schema versions load safely with an explicit error or read-only mode, without overwriting user data.
- [ ] Key storage adapter using keyring crate (target service: tech.tequity.deepaivoice) with operations: get_key, set_key, delete_key, has_key.
- [ ] Dev environment variable override: ANTHROPIC_API_KEY, DEEPGRAM_API_KEY, etc. take precedence over Keychain when resolving keys.
- [ ] Strict secrecy guarantee: JSON serialization and export never include secrets; keyRef identifiers are stored instead of raw keys.
- [ ] Comprehensive unit tests in src-tauri/tests/settings_test.rs pass with cargo test --test settings_test.

## Review findings and fixes
PR #3 review (coordinator), all four confirmed and fixed test-first:
1. Any read error fell back to writable defaults. Now only NotFound gives defaults; other errors (directory, permissions, invalid UTF-8) load read-only so save() refuses. Tests: unreadable_path_is_read_only_not_defaults_overwrite, invalid_utf8_is_read_only.
2. Failed backup rename left the file writable, and same-second backups clobbered. Now read-only on failed backup; names use millis plus a free-slot counter. Test: two_backups_do_not_clobber.
3. One bad provider or style reset all settings. Lists now parse entry by entry; bad entries are dropped and counted in `LoadResult.dropped_entries`. Test: bad_list_entry_dropped_rest_kept. wrong_types_are_backed_up_not_panicking now uses a bad `timeouts` value, since a bad list is no longer a whole-file failure.
4. v0 migration dropped raw keys silently. Provider ids (never values) are now in `LoadResult.keys_dropped` for the UI to ask for re-entry. Test: migration_reports_dropped_key_ids.
Low: schemaVersion is read once in load() and passed to migrate().
